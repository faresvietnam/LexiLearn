# Phase 3 FSRS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or **superpowers:executing-plans** to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrate automatic FSRS scheduling into the persisted learning flow without changing the learner interaction sequence.

**Architecture:** A pure rating module converts the complete attempt path to an FSRS rating. A small scheduler adapter owns the `ts-fsrs` API and maps persisted rows to/from the scheduler state. The learning session orchestrator calls both after Answer Review, then saves the card state through the existing repository boundary.

**Tech Stack:** React/Vite, TypeScript, Vitest, Supabase PostgreSQL/RLS, `ts-fsrs`.

## Global Constraints

- `desired_retention = 0.90`.
- Preserve Check → Retry → Answer Review → Continue.
- Retry failures remain `Again` evidence even when the retry succeeds.
- UI never computes intervals; FSRS owns due dates and state.
- No Gemini/Vercel Function, CSV, moderation transaction, calibration, or Stage 4 in these tasks.
- Admin remains an in-app role-gated tab; no `/admin` route.
